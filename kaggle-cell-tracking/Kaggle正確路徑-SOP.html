正確路徑 · 照順序走
STEP0

一次性：設好 Kaggle CLI（最先做）

# 1) 裝
pip install kaggle
# 2) 認證：走 OAuth（瀏覽器會自動授權）。別用舊式 kaggle.json！
kaggle auth login
# 若之前放過舊 kaggle.json，先移開免得它優先又失敗：
#   mv ~/.kaggle/kaggle.json ~/.kaggle/kaggle.json.bak
# 3) 驗證能用
kaggle competitions list
為什麼這是第一步：設好 CLi 之後，所有上 Kaggle 的事都用指令做——不用再手動拖檔、不用跟網頁編輯器奮鬥。這一步省下後面 90% 的時間。
STEP1

把 notebook 跑上 Kaggle（用 CLI）

資料夾裡放 你的.ipynb + 一個 kernel-metadata.json：

{
  "id": "你的帳號/notebook-slug",
  "title": "my notebook",
  "code_file": "你的.ipynb",
  "kernel_type": "notebook", "language": "python",
  "enable_internet": true,
  "competition_sources": ["biohub-cell-tracking-during-development"]
}
# push（含中文/emoji 一定要 PYTHONUTF8=1）→ 看狀態 → 拉結果(log)
PYTHONUTF8=1 kaggle kernels push   -p 資料夾
PYTHONUTF8=1 kaggle kernels status 你的帳號/notebook-slug
PYTHONUTF8=1 kaggle kernels output 你的帳號/notebook-slug -p 輸出夾
資料不用下載：competition_sources 一掛，資料就在 notebook 裡的 /kaggle/input/competitions/.../，程式直接讀。
STEP2

要用 GPU 跑深度學習（如 Cellpose）

metadata 加兩行——開 GPU、而且指定 T4（別用老的 P100）：

  "enable_gpu": true,
  "machine_shape": "NvidiaTeslaT4"

裝深度學習套件時，釘住現有的 numpy 跟 torch，免得它換掉弄壞環境：

import numpy, torch, subprocess, sys
NV, TV = numpy.__version__, torch.__version__
subprocess.run([sys.executable,'-m','pip','install','-q',
                f'numpy=={NV}', f'torch=={TV}', 'cellpose>=3,<4'])
為什麼 T4 不 P100：Kaggle 會隨機配 GPU。P100（2016 老卡）跑不動現在的 torch（沒對應的 GPU kernel）；T4（2018，較新）可以。一行 machine_shape 就指定到 T4。
STEP3

要知道「真分數」：用官方 metric 本地驗證

  • 別自己瞎調評分——裝官方評分套件（Evaluation 頁通常會連到主辦開源 repo）。
  • 用訓練集的答案（切一塊當「假測試」）打分 → 每改一版不用浪費提交次數就知道有沒有變好。
  • 方向先用快速 proxy 看，真數字用官方 metric 拿。
這是把分數穩定往上推的關鍵習慣：先在自己這邊比，比贏了再提交。

一句話總結：先設 Kaggle CLI（STEP 0），之後 push／跑／拉全自動；GPU 用 T4、裝套件釘版本、評分用官方尺。照這條走，我們繞的冤枉路你一條都不用走。
