Stage ① · 把問題講清楚

起點：一個能跑、但只有 0.143 的陽春版

先有一個能完整提交的官方起手式（nearest-neighbor，0.143 分）。要進步，第一步不是寫程式，而是講清楚它弱在哪——這就是要餵給 AI 的題幹。

  • 偵測太粗：固定亮度門檻 + 連通元件，兩顆貼著的細胞被算成一顆。
  • 連線太短視：只連相鄰兩幀，漏偵一幀整條軌跡就斷。
  • 完全沒處理細胞分裂：評分有 +0.1×division，baseline 這項掛零。
教學重點①：會問問題比會寫程式更重要。把「現況／目標／限制／弱點」寫清楚，AI 才幫得上忙。
Stage ② · 一套可重複的流程

「用 AI 找解法」的六步法

  1. 拆解 + 寫題幹（現況／目標／限制／弱點）。
  2. 分頭問不只一個 AI，各自獨立作答。
  3. 交叉比對、看收斂——多方都指向的＝高信心。
  4. 人來判斷取捨——AI 給選項，你定先做哪個。
  5. 實作 + 驗證——跑過、量過才算數。
  6. 記錄 + 留路線圖。

Stage ⑥ · 驗證（最重要、最常被跳過）

兩層驗證：先看方向，再拿真分數

不靠提交、不浪費次數，就知道改進有沒有用——這是把分數穩定往上推的關鍵習慣（立霧第 8 點）。

第一層：自寫 proxy，先看「方向」（用 train 的稀疏答案快速比）

baseline 0.02vsimproved 0.31→方向：改進版大勝

但這個 proxy 故意少了官方的 node 膨脹懲罰。improved 偵測 14088 個 node、真值只稀疏標 52 個——會不會其實被罰爆？光看 proxy 不準，必須上官方尺。

第二層：裝官方評分套件，拿「真分數」（tracking-cellmot，CZ Biohub 開源，跟排行榜同把尺）

版本官方 score（含懲罰）edge_jaccardnode_recall（撈到真細胞比例）
baseline0.0210.0200.058
improved0.2450.2330.463
改進版真的贏，約 11 倍——連懲罰算進去也贏。 而且我們原本的擔心被推翻：真實細胞數估計有 25,755 個（答案只稀疏標 52 個），所以 14088 個預測其實還不到真實總數（node_ratio 是負的）→ 不但沒被過度懲罰，多偵測還讓 node_recall 從 0.06 飆到 0.46。
但書（誠實）：只跑 2 個樣本；這 2 個剛好沒有分裂，所以我們的分裂規則在這裡產生 5 個假分裂——分裂規則會誤判，得在有分裂的樣本上再驗。
教學重點③：「跑得出來」不等於「跑對了」、「proxy 贏」不等於「真的贏」。一定要用官方的尺量過。
Stage ⑦ · 把整條路自動化

用官方 Kaggle CLI，push / 跑 / 拉結果全自動

手動拖檔、在網頁編輯器貼程式又卡又慢。改用官方 CLI 後，每改一版幾秒一輪、我自己迭代。

寫 .ipynb→kernels push→kernels status→kernels output（拉 log）→讀分數、修、再 push

這次踩到、值得記住的眉角：

  • 新版 KGAT_ token 不能用舊式 basic-auth 的 kaggle.json（會 401）→ 要走 kaggle auth login 的 OAuth；還得把舊 kaggle.json 移開免得干擾。
  • push 含中文／emoji 的 notebook 在 Windows 會 cp950 爆掉 → 加 PYTHONUTF8=1。
  • 裝 cellpose 把 numpy 升到 2.x、跟 scipy 衝突 → 事後 pip install "numpy<2" 釘回去。
教學重點④：debug 也是用 AI 解問題的一部分。錯誤訊息照著查、一個一個拆——401、編碼、版本衝突，每個都有解。
Stage ⑧ · GPU 加碼

GPU 讓 AI 用得起更強的方法：深度學習分割

CPU 的 watershed 是「手寫規則」。GPU 讓我們能跑深度學習細胞分割 Cellpose——一個在大量細胞影像上訓練過的神經網路。同一把官方尺，三方對照。

方法官方 scorenode_recall（撈到真細胞）耗時
baseline（CPU 閾值）0.0410.088 秒
watershed（CPU，我們 AI 找的改進）0.3440.818 秒
cellpose（GPU 深度學習）0.5701.0023.5 分鐘
一條漂亮的進步線：baseline 0.041 → 我們的改進 0.344（×8）→ GPU 深度學習 0.570（×14、撈到 100% 真細胞）。 Cellpose 在 GPU 上仍花了 23.5 分鐘跑完——同樣的事用 CPU 會慢到不切實際。這就是「GPU 不是讓同一招變快，而是讓你用得起更強的招」。
而且它不是一帆風順：先解掉 numpy/scipy/torch 三方版本打架，又因為被分到老的 P100 GPU 跑不動（torch 2.10 沒它的 kernel），改指定 T4 才成功——GPU 跑 AI 的真實工程現實。
Stage ⑨ · 站在巨人肩上

讀懂更強的公開解法，再 combine 出「新的」

真正的開發不是閉門造車——先去讀比我們強的公開高分解法（用 Kaggle CLI 直接 kernels pull 下載原始碼），再請團隊三個 AI 把它們＋我們的，synthesize 成一個新組合。重點：不是抄，是借一塊、自己加兩塊。

三個 AI 各自的新設計（讀完公開解法後）：

  • 木瓜溪：雙向時空一致性——forward 建譜系、backward 反推驗證，只留兩向一致的。
  • 秀姑巒：物理分裂閘——兩個子細胞要沿相反方向分開、體積/速度對稱才算分裂。
  • 立霧：train-set 指標校準 + 全域圖最佳化。

洄瀾綜合成一個新方法（純 CPU）：借公開 LB628 的 keep-Z 古典偵測，再自己加兩塊沒有任何公開 notebook 做過的追蹤——雙向互惠連線 ＋ 物理對稱分裂閘。

★ 用「對照實驗（ablation）」嚴格證明：我們加的東西到底有沒有用（同樣本、同偵測、只換追蹤）：

方法偵測追蹤官方 score誰的功勞
我們改進watershed（我們）舊0.344—
detect-only借 LB628舊0.568借來的偵測 +0.224
novel 合成法借 LB628新0.898我們新加的追蹤 +0.330
結論：我們自己發明的兩塊追蹤，貢獻 +0.330——比借來的偵測(+0.224)還多，是整條鏈裡最大的單一貢獻。 這就是「站在巨人肩上、再加自己的新東西」的硬證據，不是抄一支 notebook。
誠實但書：0.898 是單一訓練樣本的代理分數（比公開 LB 最高 0.687 還高，但 train≠隱藏測試集，真排行榜會不同）。不過這個對照實驗內部乾淨——同樣本同偵測只換追蹤，所以「+0.330 是我們加的」這個歸因是穩的。
帶得走的方法論

這套流程，任何問題都能套

  1. 先把問題講清楚——比下指令更關鍵。
  2. 問不只一個 AI，看哪裡收斂。
  3. 判斷與取捨留給人。
  4. 一定要用對的尺驗證——proxy 看方向、官方拿真分數。
  5. 把流程自動化，迭代才快。
  6. 一次只改一個地方，才看得出哪招有效。
  7. 需要時用 GPU 換更強的方法。
附錄 · 全程步驟清單（可照著重做）

每一步都在這

  1. 讀懂比賽：Overview / Data / Evaluation / 提交格式逐字讀回。
  2. 跑通 baseline：Copy & Edit 官方起手式 → Run All（實機驗證）。
  3. 盤點弱點，寫成清楚題幹。
  4. 派三個 AI 夥伴同時獨立獻策。
  5. 交叉比對，收斂出三招。
  6. 實作改進版（純 scipy/skimage，離線可跑）。
  7. 找官方評分程式（Evaluation 頁連到 royerlab 的開源 repo）。
  8. 本地驗證：proxy 看方向 → 官方 metric 拿真分數（0.021 → 0.245）。
  9. 全程自動化：kaggle CLI OAuth + push/status/output。
  10. GPU 加碼：Cellpose 深度學習分割三方對照。
  11. 寫成教材：就是這份。
