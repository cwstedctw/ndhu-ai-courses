先看懂 · 這是什麼問題

要教電腦做的一件事：把每一顆細胞，從頭追到底

這就是我們面對的畫面：一個發育中的胚胎，裡面上千顆會發光、會移動、會分裂的細胞。

用生活想：像看一段從天上拍演唱會的影片，你要一路盯著每一個人——他走到哪、什麼時候離場、什麼時候又多一個人。現在把「人」換成細胞、「演唱會」換成正在長大的胚胎，而且是立體的、上千顆、還會一顆分裂成兩顆。用手一顆一顆追，追到天亮也追不完。

電腦具體要交出什麼？兩件事——這也是後面每一步都圍著轉的兩個字：

  • 偵測：在每一個時間點，找出畫面裡每一顆細胞在哪。
  • 追蹤：把「同一顆細胞」在前後時間點連起來，還要認出「一顆分裂成兩顆」的時刻。
兩個半場：偵測（左）＝在每一張畫面找出細胞；追蹤（右）＝把同一顆細胞跨時間連成一條線。後面每一步，都是在把這兩件事做得更好。
怎麼打分數？（0～1，像考試，越高越好）官方用一把尺量電腦答得好不好：「前後接對」的比例越高，分數越高。但有個陷阱——亂猜、多抓一堆假細胞會被倒扣（後面第③章 ⑩ 會讓你親手拉桿玩玩看）。所以目標不是「抓越多越好」，而是又準、又不囉唆。這趟旅程，就是想辦法把分數從陽春的 0.14 一路往上推到 0.738、再挑戰更高。
Stage ① · 把問題講清楚

起點：一個能跑、但只有 0.143 的陽春版

先有一個能完整提交的官方起手式（nearest-neighbor，0.143 分）。要進步，第一步不是寫程式，而是講清楚它弱在哪——這就是要餵給 AI 的題幹。

  • 偵測太粗：固定亮度門檻 + 連通元件，兩顆貼著的細胞被算成一顆。
  • 連線太短視：只連相鄰兩幀，漏偵一幀整條軌跡就斷。
  • 完全沒處理細胞分裂：評分有 +0.1×division，baseline 這項掛零。
教學重點①：會問問題比會寫程式更重要。把「現況／目標／限制／弱點」寫清楚，AI 才幫得上忙。
Stage ② · 一套可重複的流程

「用 AI 找解法」的六步法

  1. 拆解 + 寫題幹（現況／目標／限制／弱點）。
  2. 分頭問不只一個 AI，各自獨立作答。
  3. 交叉比對、看收斂——多方都指向的＝高信心。
  4. 人來判斷取捨——AI 給選項，你定先做哪個。
  5. 實作 + 驗證——跑過、量過才算數。
  6. 記錄 + 留路線圖。

Stage ⑥ · 驗證（最重要、最常被跳過）

不靠提交、不浪費次數，就知道改進有沒有用——這是把分數穩定往上推的關鍵習慣（立霧第 8 點）。

Stage ⑧ · GPU 加碼

GPU 讓 AI 用得起更強的方法：深度學習分割

CPU 的 watershed 是「手寫規則」。GPU 讓我們能跑深度學習細胞分割 Cellpose——一個在大量細胞影像上訓練過的神經網路。同一把官方尺，三方對照。

CPU＝幾顆很會「想」的腦袋（少而聰明、擅長邏輯判斷）；GPU＝一大群核心同時算（多而並行、擅長把幾百萬像素一次看完）。看任務挑工具，不是誰比較強。
知其所以然：為什麼深度學習偏好 GPU？深度學習「認圖」是同一種簡單運算、在幾百萬個像素上重複做——正好是 GPU「一大群核心同時算」的強項。用 CPU 做同一件事會慢到不切實際。所以重點不是「GPU 讓同一招變快」，而是「GPU 讓你用得起原本跑不動的更強方法」。

一條漂亮的進步線：baseline 0.041 → 我們的改進 0.344（×8）→ GPU 深度學習 0.570（×14、撈到 100% 真細胞）。 Cellpose 在 GPU 上仍花了 23.5 分鐘跑完——同樣的事用 CPU 會慢到不切實際。這就是「GPU 不是讓同一招變快，而是讓你用得起更強的招」。
而且它不是一帆風順：先解掉 numpy/scipy/torch 三方版本打架，又因為被分到老的 P100 GPU 跑不動（torch 2.10 沒它的 kernel），改指定 T4 才成功——GPU 跑 AI 的真實工程現實。
Stage ⑨ · 站在巨人肩上

讀懂更強的公開解法，再 combine 出「新的」

真正的開發不是閉門造車——先去讀比我們強的公開高分解法（用 Kaggle CLI 直接 kernels pull 下載原始碼），再請團隊三個 AI 把它們＋我們的，synthesize 成一個新組合。重點：不是抄，是借一塊、自己加兩塊。

站在巨人肩上：先讀懂比我們強的公開解法，再站上去、加上自己的新東西——才看得更遠，也才不是抄。

三個 AI 各自的新設計（讀完公開解法後）：

  • 木瓜溪：雙向時空一致性——forward 建譜系、backward 反推驗證，只留兩向一致的。
  • 秀姑巒：物理分裂閘——兩個子細胞要沿相反方向分開、體積/速度對稱才算分裂。
  • 立霧：train-set 指標校準 + 全域圖最佳化。

洄瀾綜合成一個新方法（純 CPU）：借公開 LB628 的 keep-Z 古典偵測，再自己加兩塊沒有任何公開 notebook 做過的追蹤——雙向互惠連線 ＋ 物理對稱分裂閘。

第一招「雙向互惠連線」：不只從前往後找最近的，也從後往前再確認一次——兩邊都指到對方才連，密集時大幅減少接錯。
物理對稱分裂閘的直覺：真的分裂時，兩顆子細胞會往相反方向分開（像被輕輕掰成兩半）。不是往相反方向的，就不算分裂、只是剛好擦身而過——用這個物理常識擋掉假分裂。
知其所以然：為什麼用「物理」而不是純資料？純看資料，兩顆靠近的細胞和「一顆剛分裂的細胞」長得很像，很容易誤判。但分裂有物理規律：子細胞會沿相反方向、對稱地分開。把這個常識寫進規則當「守門員」，就能用很少的計算擋掉大量假分裂——這叫用領域知識當約束，常比硬堆模型更有效。

Stage ⑩ · 再上一層：泛化

0.701 → 0.738：讓它在「沒看過的胚胎」上也穩

0.701 很好，但我們發現它在不同胚胎上時好時壞。改用 5 個 train 樣本＋官方尺一起量（比只看單一樣本更接近真實），再加兩招讓它更穩：

加的招做法為什麼有用
局部自適應正規化用「這一小塊的亮度」當基準，而不是拿整張圖比不同胚胎、不同深度亮度差很大；用局部基準，暗處的細胞也浮得出來
剪掉孤立節點把「沒連上任何線」的偵測點刪掉沒連上的點幾乎都是雜訊（假細胞），留著只會被扣分
知其所以然：為什麼「少而精」會贏？官方分數裡有一項乘數 ×(1 − 0.1×節點膨脹比)——你多預測的假細胞越多，這個乘數越小、分數被打越低。所以「拚命多抓」不會贏，「抓得準、少廢話」才會。robust 用更少節點（44541→42214）換到更高精準度（0.672→0.691）。
🎛️ 玩玩看：為什麼「多抓」反而扣分

假設你的連線品質固定（edge Jaccard = 0.80）。拉一下拉桿，看「多預測的假細胞」怎麼把分數一口口吃掉：

多抓的假細胞0% 懲罰係數1.00 最終分數0.80

綠＝真細胞、紅＝多抓的假細胞。示意用，與官方公式精神相同：過度偵測會被乘上一個小於 1 的懲罰係數。

結果：5 樣本平均 0.6605 → 0.6779，真實排行榜 0.701 → 0.738（+0.037）。本地 5 樣本 novel≈0.66 對上真實 LB 0.701，代表這把「5 樣本的尺」量得準、能拿來預測排行榜。
Stage ⑪ · 一個被誤判的天花板

難樣本一直漏細胞——不是找不到，是被「黏在一起」了

有些胚胎很密集，我們一直漏掉快一半的細胞（recall 0.51），一度以為古典法到頂了。後來查出真相：是我們為了跑快、把圖縮太小，把靠近的細胞糊成一團了。

粗網格（左）把兩顆靠近的細胞看成一顆；看得細一點（右）就分得開了。

原本 XY 方向縮小 4 倍再找細胞；改成只縮 2 倍（看得更細）後：

難樣本 recall 0.51→0.745一口氣拉起來
知其所以然：解析度 vs recall 的權衡把圖縮太狠＝省時間，但兩顆靠近的細胞會被壓成同一格、看起來像一顆（漏掉）。看得越細＝找得到越多真細胞，代價是也冒出更多假的、而且更慢。這是一個要調的旋鈕，不是古典法的極限——先前的「天花板」是自己縮圖縮出來的。
代價：看得細之後假細胞暴增（易樣本 13k→87k 個點），過度膨脹懲罰又把分數壓下去——這就帶出下一關。
Stage ⑫ · 先抓多、再修剪

計數校準：既不漏、也不爆

看得細之後「真細胞找齊了，但假細胞也一堆」。公開高分解法的關鍵一招：先放寬抓多，再依分數把每部影片修剪到合理的細胞數——稀疏胚胎少留、密集胚胎多留。

知其所以然：為什麼一個固定門檻不夠？不同胚胎的細胞數差好幾倍。用同一個固定門檻，稀疏的會被抓太多（一堆假的）、密集的會被抓太少（漏一堆）。改成「每部影片各給一個節點預算」，放寬偵測先把真細胞都撈進來、再按分數修到預算內，就能兩邊都顧到。

加上這招，純 CPU 版本地推到 0.6928。但也看到純 CPU 古典法的天花板大約在 0.74–0.75——要再往上，得換更聰明的引擎。

Stage ⑬ · 換更聰明的引擎（進行中）

ultrack：不急著選一個門檻，讓演算法自己挑

前面每一步，我們都得「先選定一個門檻、一種偵測」，選錯就輸。ultrack（正好是這場比賽主辦 Royer lab 自家的 SOTA 工具、就是拍這批資料的同一組人）換了個思路：

知其所以然：多假設 + 全域最佳化不要一開始就硬選一個門檻，而是同時保留很多種可能的細胞分割（候選），再用「同一顆細胞在時間上要連貫」這個條件，讓一個全域最佳化（整數線性規劃 ILP）一次挑出最合理的一整組。這天生就解掉我們「看得細→假細胞爆量」的兩難——它會自己把不連貫的假細胞挑掉，不必再硬套計數預算。
  • 為什麼最對路：這批資料就是 Royer lab 用光片顯微鏡拍的；官方評分也用他們的工具；主辦自己的示範解也是這個路數。用作者的工具解作者的題，最合理。
  • 能離線跑：內建免費解算器（不必付費授權），符合 Kaggle「提交時不能上網」的規則。
狀態（誠實）：正在把它接上我們的管線、測 199 片測試資料的時間吃不吃得下。就算最後沒衝到 0.85，這趟「怎麼一步步逼近、每一步為什麼」才是這份教材真正要教的。
帶得走的方法論

這套流程，任何問題都能套

  1. 先把問題講清楚——比下指令更關鍵。
  2. 問不只一個 AI，看哪裡收斂。
  3. 判斷與取捨留給人。
  4. 一定要用對的尺驗證——proxy 看方向、官方拿真分數。
  5. 把流程自動化，迭代才快。
  6. 一次只改一個地方，才看得出哪招有效。
  7. 需要時用 GPU 換更強的方法。
  8. 先量再下結論，別急著照抄——別人的招不一定適合你（計數校準對我們就是多餘的）。
  9. 撞牆先問「是不是自己設限」——我們以為古典法到頂，其實是自己把圖縮糊了。
附錄 · 全程步驟清單（可照著重做）

每一步都在這

  1. 讀懂比賽：Overview / Data / Evaluation / 提交格式逐字讀回。
  2. 跑通 baseline：Copy & Edit 官方起手式 → Run All（實機驗證）。
  3. 盤點弱點，寫成清楚題幹。
  4. 派三個 AI 夥伴同時獨立獻策。
  5. 交叉比對，收斂出三招。
  6. 實作改進版（純 scipy/skimage，離線可跑）。
  7. 找官方評分程式（Evaluation 頁連到 royerlab 的開源 repo）。
  8. 本地驗證：proxy 看方向 → 官方 metric 拿真分數（0.021 → 0.245）。
  9. 全程自動化：kaggle CLI OAuth + push/status/output。
  10. GPU 加碼：Cellpose 深度學習分割三方對照。
  11. 站在巨人肩上：讀公開高分解法、combine 出自己的新法（排行榜 0.701）。
  12. 再上一層泛化：局部正規化＋剪孤立節點，排行榜 0.738。
  13. 找出真瓶頸：解析度縮太狠把細胞黏住了→細解析度＋計數校準。
  14. 換 SOTA 引擎：ultrack 多假設 ILP，挑戰更高（進行中）。
  15. 寫成教材：就是這份。
