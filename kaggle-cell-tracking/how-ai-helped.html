🤖 一個 AI Agent 怎麼幫忙解一場真實比賽 Claude Code × Kaggle

00 這是什麼

不是聊天，是「動手」：
一個 AI Agent 的解題日記

這份文件不講細胞生物學（那份在另一頁）。這裡要給你看的是幕後——一個 AI agent（Claude Code，我們叫它「洄瀾」）和一位老師（文盛老師），怎麼合力去解一場真實的國際 AI 競賽，以及這個 AI 到底「能做什麼」。

💡 還不清楚這場比賽在解什麼？建議先看科普姊妹頁《生命，是怎麼長出來的？》（就是上面那個「另一頁」連結），再回來看幕後，會更好懂。

先講結論

在一個 500 多隊、獎金約新台幣 200 萬的國際細胞追蹤賽裡，我們爬到 0.897 分（滿分 1.0）、大約第 10 名，離世界第一只差 0.009。老實說：這分數大部分是「讀懂並重現公開的作法 ＋ 調參數」換來的，加上一點我們自己的東西。而這一路，AI agent 不只出一張嘴，它親手跑程式、開雲端 GPU（專門算 AI 的高速晶片）、自己除錯、自己重新登入、找另一個 AI 幫畫圖，還做出了你正在看的這個網頁。

很多人以為「AI」就是問一句、答一句的聊天機器人。這份文件想讓你看到另一種 AI——agent（代理人）：你給它目標，它會自己規劃、動手用工具、遇到錯誤自己修、跑不完的活自己排隊等，像一個很勤快、動作很快、但需要你把方向的隊友。

上面的頁籤可以跳著看。建議順著看：舞台與傢伙 → 歷程 → 方法與抉擇 → AI 幫了什麼 → 給你的啟示。

01 舞台與傢伙

這局是怎麼「接起來」的

要看懂 AI 能幫什麼，先看它手上有哪些傢伙、跟誰配合。

台上的角色

🧑‍🏫人（文盛 老師）

定方向、做判斷、把關、對不可逆的動作（例如按下提交）拍板。也負責在 AI 太早喊「到頂了」時踹一腳。

🤖AI agent（洄瀾）

那雙手：讀寫程式、跑指令、開雲端運算、盯結果、除錯、寫報告、做教材。動作快、不喊累，但需要人把方向。

☁️Kaggle（賽場）

全球 AI 競賽平台，還提供免費雲端 GPU。重的模型不在老師的筆電上跑，是送到 Kaggle 的伺服器上算。

AI 實際會操作的工具

這些不是比喻，就是這個 agent 真的在用的東西（下面那行指令看不懂沒關係，重點是：這些都是 AI 自己打出來的）：

agent 把一份 notebook（能一格一格跑的程式檔）送上 Kaggle 的雲端 GPU 跑
$ kaggle kernels push -p ./experiment
→ Kernel version 1 successfully pushed（在 Kaggle 的 T4 GPU 上開始跑）
$ kaggle kernels status chenwensheng/experiment
→ COMPLETE　$ kaggle competitions submit ... -f submission.csv

⌨️指令列自動化

把程式送上 Kaggle、在雲端跑、拉回結果、提交，全用指令，不用手動拖檔、不用跟網頁編輯器奮鬥。

☁️借別人的 GPU

3D 深度學習模型很吃算力。agent 把工作外包給 Kaggle 的雲端顯示卡（兩張 T4），自己只負責指揮與收結果。

🔑自己重新登入 ★

登入權杖（登入用的通行證）每小時就過期。以前得請老師手動重登；後來 AI 學會自己重登，打開登入頁、按授權、讀回授權碼、餵回工具，全程自己來。

🎨找 AI 隊友

要畫插圖時，agent 把任務派給另一個 AI（立霧，跑在別家模型上），它畫、回報，洄瀾再驗收挑選。

誠實：能做什麼、不能做什麼

能：跑程式、開雲端運算、讀寫檔案、除錯、排隊等結果、寫報告與網頁、派工給別的 AI、自己重新登入。
不能（或不該自己來）：定大方向、做價值判斷、對「不可逆」的動作（送出提交、刪東西、對外發布）拍板，這些留給人。AI 是很強的手，方向盤還在人手上。

02 歷程

從 0.738 爬到 0.897：每一步為什麼

分數越高越好。粉紅＝我們自己做的、藍綠＝重現/借公開的。重點不只在數字，在每一步為什麼這樣走。

  1. 0.738
    我們從零自己寫的管線 我們的
    先自己動手做一版，用「做得出來」逼自己真的搞懂問題。能跑，但卡住。AI 幫的：寫出整條偵測＋連結的程式、反覆試。
  2. 0.857
    重現公開的古典解法 ＋ 補「軌跡平滑」 借的
    為什麼轉向？老師的規矩：動手改自己的碼前，先查排行榜＋別人公開的作法。一查發現有人把 code 公開了，還缺一招「把抖動的路徑拉直」。AI 幫的：讀懂公開程式、找出我們缺的那一招、重現。
  3. 0.885
    重現公開的 AI 模型解法 借的
    最大領悟：連「訓練好的模型權重」（模型學到的本事，存成一份檔案）都是公開的。我原本一口咬定是別人的秘密，結果一查就在那。別假設有牆，去看真實狀態。
  4. 0.890
    把公開最強零件組起來 ＋ 我們的過濾 大多借的
    把最好的公開零件拼起來，加上我們自己寫的「乾淨過濾」。AI 幫的：一個個試哪種組合有效、比較結果。
  5. 0.897
    把一顆參數調對 我們調的
    老師一再提醒：別急著喊「這就是極限」，還有參數可以調。把 AI 最佳化器的一顆旋鈕從 0.1 調到 0.3，就多了 0.007 分、衝進前段。他不只一次這樣提醒，而且每次都對。
  6. 0.906
    世界第一（別隊、解法不公開）
    我們離榜首只差 0.009。我們也交出了「自己微調的模型」試著超過公開前線，分數計算中。
這一頁最重要的兩句話（都是人教 AI 的）

① 動手前先查別人公開了什麼，重現比重造聰明。
② 別太早喊到頂，很多次以為到極限，一調參數又上去了。

03 方法與抉擇

為什麼換、為什麼選：藏在分數後面的判斷

每一次「換方法」都不是亂試，背後有理由。這頁把幾個關鍵決定攤開講。

① 先「規則法」，再「AI 模型法」

規則法＝寫死的步驟（找亮點、把近的連起來），好懂、跑得快。AI 模型法＝訓練一個神經網路（一種像大腦、會從例子學習的模型）自己認細胞、自己判斷該連誰，比較聰明、能抓到暗淡細胞。
為什麼這樣排？先用規則法親手做，是為了真的搞懂問題長怎樣；等摸透了、也撞到規則法的天花板，再轉去重現更強的 AI 模型法（天花板更高）。

② 為什麼一路「往精準、不往貪心」走

這場比賽的計分有個怪脾氣：猜太多會扣分。所以我們每次想「多抓一點細胞」都是負分收場，反而「清乾淨、連準確」才加分。這個發現直接決定了後面所有調整的方向，包括那顆讓我們從 0.890 上到 0.897 的旋鈕（它的作用正是「叫最佳化器少開一些可疑的新軌跡」）。

AI 怎麼幫

同一份資料，AI 反覆做「加一點 / 減一點」的對照實驗，把「多抓細胞反而傷分」這條規律驗證了三、四次才敢當結論，不是憑感覺，是拿真實分數反覆確認。

③ 那一招讓分數跳最多：軌跡平滑

從 0.738 跳到 0.857，靠的不是高深模型，而是一招「軌跡平滑」：細胞真正的路徑其實蠻順的，但電腦每一格量到的位置會抖來抖去，抖動害得連連看連錯。把位置拉順，配對一下就準了。問題不在抓多抓少，在量得夠不夠準。這一步點破了我們卡關的矛盾。

④ 最後一搏：微調（fine-tuning）我們自己的模型

微調＝拿一個已經訓練好的模型，再用資料多教它一點點。這是現在 AI 最主流的做法。
為什麼試？想做出一塊「真正屬於我們、能贏過公開前線」的東西。
為什麼可能沒用？我們拿去微調的資料，就是那個模型早就看過的同一批，等於叫一個老師傅把他本來就會的菜再練一次，可能更順、但不會突然變神。所以我們只輕輕推（怕它「背太熟、換題目反而退步」）。到底有沒有用，要等比賽分數，不自己說有效。

AI 怎麼幫

AI 把公開的訓練程式接起來、補好接口、在雲端 GPU 上訓練、把訓練好的權重打包、再送去比賽，這整條「自己訓一個模型」的流程，都是 agent 一手串起來的。

04 這才是重點

攤開來看：AI agent 到底幫了哪些

下面每一項，都是這次真的發生的事。這也是為什麼我們覺得它是「AI agent 怎麼幫人」的好例子。

🧪大量跑實驗

把幾十個「參數不同」的版本一個個送上 Kaggle 雲端跑，拉回結果、比較優劣，換人手動做，要熬好幾個通宵。

🔀自己排隊、自動提交

雲端一次只能跑 2 個、一天只能交 5 次。AI 寫了一支背景程式替自己排隊：跑完一個就補下一個、驗證沒問題就自動提交，連續顧好幾個小時。

🐛自己除錯

過程踩到三個工具坑（名字卡住、權限唯讀、狀態誤判把成功當失敗）。AI 自己診斷、自己繞過，還把一個被誤判成「失敗」、其實已經跑完的結果救了回來。

🔑自己重新登入 ★

登入權杖一小時就過期。AI 學會自己重跑登入流程（開頁面、按授權、讀回授權碼、餵回去），不用每次都叫醒老師。

🎨找隊友補能力

自己不擅長畫圖，就把畫圖派給另一個 AI（立霧）；畫完逐張把關，還擋下一張「看起來像精子、會誤導學生」的圖，請它重畫。

📄做出互動教材

你正在看的這個多頁互動網頁、還有另一份能播放縮時影片的科普頁，都是 AI 寫的 HTML／CSS／JavaScript，而且在真的瀏覽器裡測過會動。

背景編排器：跑完就交、連續顧好幾小時
[10:34] SUBMITTED ilp5x (246,994 rows)
[10:36] SUBMITTED det995x (244,534 rows)
[10:45] SUBMITTED combo → ===== ALL DONE =====
// 一個被誤判失敗的結果，AI 查出其實已完成、手動救回並補交
但是，方向盤還在人手上

這局能成，靠的不只是 AI 勤快。是老師定方向（要做這場比賽、當教學專案）、做判斷（「先查公開的」「別喊到頂」都是他教的）、把關拍板（每次不可逆的提交、要不要用某張圖）。AI 把「重複、繁瑣、要快、要熬夜盯」的部分扛走，人專心在「想清楚、下判斷」。這才是好的分工。

05 帶走這幾點

如果你也想用 AI 解一個真問題

🧭你負責方向，AI 負責動手

你不用會寫全部程式。你要會的是：想清楚問題、做判斷、把關，然後讓 AI 去跑、去試、去除錯。

🔍先站在別人肩膀上

動手前先查「別人公開了什麼」。重現＋讀懂＋改一點，比從零重造聰明太多，真實世界的 AI 幾乎都這樣做。

🧗別太早說「到頂了」

我們好幾次以為到極限，一調參數又上去。先確認那真的是牆，再放棄。

🤝誠實分清楚來源

哪塊是你的、哪塊是借的、哪塊是 AI 做的，說得清楚，本身就是專業。

一句話總結

AI agent 是一雙很強、很快、不喊累的手；但要它幫上忙，你得先成為那個「會想、會判斷、會把關」的腦。這場比賽就是一個活生生的例子：人＋AI，各做自己最擅長的那一半。
